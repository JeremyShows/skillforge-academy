# Contributing to SkillForge Academy

Contributions are welcome for the course runtime, certification study experience, original learning content, accessibility, testing, and documentation. Begin with the [contributor onboarding guide](docs/contributor-onboarding.md); it explains the supported setup, architecture, validation, and RepoPact process.

For a substantive change, work from an accepted RepoPact item. Contributors may propose a new item or scoped record change through an issue or pull request, but only maintainers create or accept canonical work-item records. Contributors do not approve RepoPact items or merge their own pull requests. Keep work within acceptance criteria, preserve learner data and backup compatibility, and attach command evidence. Open a focused pull request against `main` and request independent technical review for architecture, persistence, privacy, content, accessibility, or release changes.

All submitted learning material must be original. Do not contribute recalled live exam questions, exam dumps, reconstructed vendor PBQs, proprietary answer keys, private course material, credentials, or local machine paths. Use public package contracts and sanitized examples for any optional integration.

The active default-branch repository ruleset requires pull requests and protects against deletion and non-fast-forward updates. It does not require an approving review, latest-push approval, or code-owner approval. The `CODEOWNERS` file identifies maintainers for protected paths and can support voluntary reviewer requests after it is present on the base branch. Formal GitHub approval is optional under the current single-maintainer model. Independent technical review remains required when a RepoPact acceptance criterion or governance decision specifies it; that review does not replace required tests, command results, or acceptance evidence. Mandatory human approval can be introduced when qualified non-author maintainers are available. RepoPact validates record schemas and evidence but does not authenticate who authored a record; rejecting a non-maintainer proposal by identity before review would require custom CI that is not currently configured. See the onboarding guide for the verified process and commands.
